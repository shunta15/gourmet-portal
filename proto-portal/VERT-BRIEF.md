# 業種トップ(ビューティー・ボディケア)デザイン案 — 共通ルール(2026-10-08)

## 発注者の依頼
- 「ビューティとボディケアのデザインを 5 案ずつ製作してください。デザインのクオリティはわかってるよね？」
- クオリティの基準(発注者の言葉): 「Awwwards や Webby Awards、FWA で賞を穫れるくらいのクオリティを目指して、セルフチェックでそのクオリティ基準になるまで自分でクオリティアップを繰り返して」。
- 決まっていること: 総合トップは「にぎわいの輪」(料理の写真の輪・丸ゴシック・白磁と藍／濃紺と銅)。グルメは「暖簾」(夜の街・墨と生成りと朱・明朝・大きな漢字の暖簾の布)。
  ビューティーとボディケアも、**その業種だけの世界**を 1 つ持つ。10 人の担当が 1 案ずつ作る。設計書は `proto-portal/vert-concepts/<案の名前>.md`。**設計書の世界(色・書体)・主役の絵は変えない**。作り方は任せる。

## これまでに発注者から言われたこと(必ず読む)
1. 前に 5 案を見せたとき: 「なんでデザインが全部これなの。カスじゃねぇかよ」。5 案とも「生成りの紙の地・黒い明朝・細い線の円・写真なし」で、互いに同じに見え、地味だった。
   → **禁止**: 「生成りの地＋黒い明朝＋細い線」の組み合わせ。図や資料に見える画面。おとなしい・無難な画面。開いた瞬間の 1 枚が勝負。
2. 色ちがいを見せたとき: 「ただの色で分けるんじゃなくて、高級感ある色とか」。→ 色は、地・文字・差し色・線・影まで含めて 1 つの世界として組む。
3. 暖簾の特集記事を見せたとき: 「暖簾にしてる意味を感じない」。色と書体だけ合わせて、主役の仕掛けが別物だった。
   → **主役の絵(モチーフ)は飾りではなく、ページの作りそのもの**にする。最初の画面だけでなく、下の各ブロックにも同じモチーフが、理由があって出てくること。
4. 総合ページについて: 「シンプルに作ってほしい」。→ シンプルにするのは構成。見た目は強く。
5. 前(10/06)に作ったビューティー・ボディケアの 10 案(櫛・鏡・糸・塗る・光／呼吸・押す・湯・ほぐす・整う)は選ばれなかった。多くが「白か生成りの地に差し色 1 点」だった。同じ主題・同じ見た目にしない。

## 1. ページの中身(どの案も同じ。**今のページと同じ中身・同じ言葉**)
今の業種トップ `components/portal/VerticalHub.tsx` を読む(読むだけ。変えない)。データも同じ取り方で(`lib/verticals/<業種>.ts`、件数は同じ関数)。出すもの:
1. 最初の画面(100svh): 主役の絵／業種の名前(ブランド名「マチノワビューティー」「マチノワボディケア」)／状態(掲載 0 件のあいだは「掲載準備中」。「現在の掲載 0 件」「種類 N」「利用シーン N」)／リード(今のページの 1 文)／種類(6 つなど。今と同じ行き先 `/beauty/<slug>` など)／ロゴ(マチノワ → `/`)／「さがす」(→ `/find`)。
2. その下: 「種類から探す」「エリアから探す」(都道府県。今と同じ行き先・同じ数)「利用シーンから探す」「掲載準備中です」(今の説明文・掲載方針・「掲載基準」「掲載のご相談」の行き先)「ほかの入口」。パンくずに当たる行き先(マチノワ → `/`)も。
3. その下は共通フッター(枠が付ける。部品は変えない。**色だけ**、自分の案の画面のあいだだけ合わせてよい: `body:has(.自分の接頭辞)`)。
- **言葉**: 画面に出す文は、今のページにある文(一字一句そのまま)と、データにある名前だけ。新しい宣伝文・説明文を足さない。飾りの欧文は「MACHINOWA」と業種の英名(BEAUTY / BODYCARE)、種類の slug だけ。
- **作らない**: 店・店名・写真・件数・開始時期。掲載 0 件は 0 件と出す。星・点数・順位・「おすすめ」「人気」。効果・効能を思わせる言葉(各業種の `copyRules` の禁止語。絵で表すのはよいが、言葉を足さない)。
- 人の顔・体の絵は描かない(抽象的な物・素材・光・動きで表す)。

## 2. 使ってよいもの・場所
- ルート: `app/proto-hub/<業種>-<案の名前>/page.tsx`(例 `app/proto-hub/beauty-tsuya/page.tsx`)。`robots: { index: false, follow: false }`。ページの先頭で `isPreviewOrLocal()`(`lib/portal/launch.ts`)を見て、偽なら `notFound()`(プレビューとローカルだけで開く)。
  枠 `app/proto-hub/layout.tsx`(共通ヘッダーなし・共通フッターあり)はそのまま使う。ヘッダーに当たるもの(ロゴ・さがす)は自分の案の中に作る。
- 部品と CSS: `components/portal/vert/<案の名前>/**`。データ処理: `lib/portal/vert/<案の名前>/**`。**触ってよいのはこの 3 か所だけ**(共通の部品・設定・ほかのページは変えない)。
- 書体: Google Fonts を使ってよい(`components/portal/PortalFonts.tsx` と同じやり方で、自分の部品から `<link rel="stylesheet" precedence="default">`。使う太さだけ。`display=swap`)。
- 絵: CSS・SVG・Canvas 2D・手書きの WebGL(ライブラリなし。使えないときの代わりの絵を必ず用意)。新しい npm パッケージは足さない。外部の画像・写真は使わない。音は付けない。
- `"use client"` の部品から `@/lib/data` などの巨大なデータを import しない。実行時に `fs` で `public/` を読まない。
- サイト共通の丸いカーソルが邪魔なら、自分の画面のあいだだけ消してよい。

## 4. 質(ここが本題)
- 採点は Design 40 / Usability 30 / Creativity 20 / Content 10。**自己採点で 加重 8.5 以上・全項目 8.0 以上になるまで作り直す。最低 3 周**。毎周、自分のスクショを**自分の目で見て**、弱点を 5 つ以上書いてから直す。点は盛らない。
- 毎周見ること:
  - 開いた瞬間の 1 枚(PC 1440×900・スマホ 390×844)が、設計書の世界で、強いか。止まった絵でも成立するか。「生成りに細い線」の地味な絵になっていないか。ほかの 4 案と見分けがつくか。
  - 主役の絵が、触って気持ちよいか(マウス・タッチ・慣性)。触る前に、触れると分かるか。
  - 下の各ブロックにも主役のモチーフが、理由があって出ているか(最初の画面だけ豪華で、下が普通の一覧になっていないか)。都道府県 47 個のような長い一覧も、その世界で、読みやすく美しく。
  - スマホは別に設計する(押し所 44px 以上、最小の文字 12px、大事な情報は 13px 以上)。1280×720・360×640 でも、はみ出し・重なり・文字の切れが無い。
  - 文字のコントラスト 4.5:1。安い見え方(虹色のグラデーションのベタ塗り・ゲームのような光り方・素人っぽい影)になっていないか。
- 軽さ: 毎コマ React の state を書かない(値は ref と CSS 変数、動かすのは transform と opacity)。画面外・タブが裏のときは描画を止める。高精細な画面では描画の解像度に上限を付ける。フレーム間隔を測る(主役の動き。CPU 4 倍遅延でも)。
- `prefers-reduced-motion`: 動きを止め、同じ行き先に届く静かな画面。スクリプトなしでも、中身が全部読めて、全部の行き先に届く。WebGL が使えないときの代わりの絵。
