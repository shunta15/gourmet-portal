# おまかせ提案（/omakase）— 結び付けの表と、数えた結果（2026-10-06・試作）

オーナーの承認（「誰と」「予算」「気分」の3問に、「どこで」を最初の質問として足した4問）。4つの質問に答えると、条件に合う店を3軒ほど出す。**公開スイッチ ON のときだけ**（OFF は `/omakase` が 404。`/` `/search` ほか既存ページの出力は変えない）。
画面は `components/portal/omakase/`（`OmakaseApp.tsx`・`Results.tsx`・`Pool.tsx`・`CountRoll.tsx`・`useShops.ts`）と `components/portal/omakase.css`、判定は `lib/portal/omakaseDefs.ts`（質問・結び付け・判定・URL）・`omakaseRows.ts`（店の表）・`omakase.ts`（サーバー）。
この表は **`node --env-file=.env.local proto-portal/count-omakase.mjs [--md 出力.md]`** で数え直せる（店は本番と同じ `getAllRestaurants()`、判定は画面と同じ関数）。単体テストは `node proto-portal/test-omakase.mjs`（124 件）。
下の数字は、2026-10-06 に上のコマンドで出した実測値（全店 **513 店**）。

## 0. 選択肢と事実の結び付け（全部）

事実だけを使う。根拠になるデータが無い選択肢は作っていない。条件は「全部を満たす店」に絞る。判定できない（不明の）店は、その質問を選んだときは含めない。各質問に「どれでもよい」（場所は「どこでも」）がある。

## 4. 自分で決めたこと（解釈・除外・閾値）

1. 気分の語は、`CUISINE_GROUPS`（/search のジャンル）の語に、表記ゆれ（蕎麦・イタリア料理・フランス料理・麺類・京料理・会席・ステーキ・うなぎ・Bar など）を足した。
   `CUISINE_GROUPS` だけだと、業態が「蕎麦店」「イタリア料理店」「フランス料理店」の店が、麺・洋のどちらにも入らない。`lib/cuisineGroups.ts`（グルメの既存ページが使う）は変えていない（OFF の出力を変えないため）。
   - 「郷土料理」は和の語から外した（「イタリアン（マルケ州郷土料理）」を和に入れないため）。「ハンバーガー」は「バー」を取り除いてから酒の語を探す。
   - どの気分にも入らない業態は 30 店（レストラン 16・パン 2・惣菜・創作料理・メキシコ料理・ナイトクラブ・ハンバーガー・アメリカンダイナー・ベーカリー・鮮魚店・串揚げ串カツ店・精肉店・フランス菓子店ほか）。「気分は問わない」では出る。
2. 「誰と」の結び付けは、データの事実から決めた（オーナー確認用）。「個室」を「ふたり」に、「カウンター席」を「ひとり」に当てるのは解釈。座席数（20席以上など）は、誰と にもなりうるが、容量の事実であって同行者の事実ではないので使っていない。
   「誰と」のどの選択肢にも当てはまらない店が 243 店（半分近く）あるので、「誰と」を選ぶとその店は出ない。
3. 予算は「予算が書かれていない店」（238 店）が、予算を選ぶと出ない。帯は/searchの `?budget=` と同じ意味（1,001〜3,000 円は「上限が 1,001〜3,000 円」）。
4. 結果の 3 軒は、当てはまる店を URL の種（`?s=`）で決まる順に並べて先頭から 3 軒（`?n=` で次の 3 軒）。評価・人気・距離・新しさは使わない。同じ URL なら同じ 3 軒が出る（共有できる）。種が無い URL は固定の種 `0`。
5. 結果の画面は、当てはまる店が 3 軒に満たなくても、ある分だけ出す。どの条件をゆるめると店が増えるかを、件数つきで出す（0 店のときも）。条件に合わない店は混ぜない。
6. 質問ごとに、選択肢の店数は「ほかの答えをかけた状態でその選択肢を選んだときの店数」。0 店の選択肢は押せない（`aria-disabled`・Tab では届く）。
7. 「この条件の N 店を、すべて見る」は `/search?r=…&who=…&b=…&m=…` に飛ぶ。`/search`（ON のとき）が同じ答えを読み、同じ判定（`omakaseRowOf`）で絞る（画面の店数・/search の件数・実データの数え直しが 12 通りすべて一致することを確認）。
   `/search` でキーワードなどを変えると、おまかせの答えは外れる（こだわり条件だけが引き継がれる）。`SearchClient.tsx` に手を入れない（OFF の出力を変えない）ための割り切り。
8. SEO: 答え（`?r=` `?p=` `?who=` `?b=` `?m=` `?q=` `?s=` `?n=` のどれか）がある URL は `noindex, follow`・canonical `/omakase`。答えの無い `/omakase` だけ、掲載店 3 店以上で index（`lib/seo/gate.ts`）。サイトマップには載せない（入口は `/gourmet` のリンク）。

## 5. 画面の動きと、止めかた

- ふるい（`Pool.tsx`）: 掲載店 1 軒 = 点 1 つ。答えるたびに、条件に合う店だけが墨の点で残る。選択肢を指すと、それを選ぶと残る店が朱で見える。結果の 3 軒は朱の点＋輪＋壱・弐・参。
- 暖簾（`Results.tsx` + CSS）: CSS だけ（WebGL・ライブラリなし）。落ちる → 揺れて待つ → 巻き上がる。「ほかの候補を見る」は、いま出ている店の上に布が落ち、裏で入れ替えて、また上がる。
- 動きを減らす設定（`prefers-reduced-motion`）: 暖簾・飛ぶ文字・点のさざ波・登場の動きをすべて止める。店はすぐ出る。
- 点の描画は rAF で、動いているあいだだけ回る（止まれば停止）。canvas は `aria-hidden`、店数は文字（`role=status`）でも出す。
