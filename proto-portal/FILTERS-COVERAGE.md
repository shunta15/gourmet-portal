## 2. 決まりの補足（仕様の表に書いていない細部で、読み取りのために決めたこと）

仕様の「判定の決まり」は変えていない。次は、文字列を読むときに決めた細部。疑問は最終報告にも書いた。

1. **予算**（`lib/portal/facetParse.ts` の `budgetYen`）
   - 帯は「書いてある上限」。`¥3,000〜` のように上限が無ければ下限、`N円前後` は N。昼と夜があれば夜（ディナー）、夜が無ければ昼（ランチ）。
   - 読まない（不明にする）もの: 「要確認」、「3,000円台」「千円」など曖昧・漢数字、料理の単品価格・ドリンクだけの値段、
     夜（ディナー）と書いてあるのに金額が読めない（「ディナー 予約制」「ディナー 4,000円台〜」）とき（昼の値で代用しない）、
     昼夜の表示が無い値が 2 つ（「501円~1,000円/2,001円~4,000円」。どちらが夜か分からない）。括弧の中の注記は読み飛ばす。
   - 帯の表示は、混同を避けるため範囲を明記した（「〜1,000円」「1,001〜3,000円」「3,001〜5,000円」「5,001〜10,000円」「10,001円〜」）。
     1店はちょうど1つの帯に入る（「〜3,000円」を選んでも、〜1,000円の店は含まれない）。URL の `?budget=` は帯の上限（1000 / 3000 / 5000 / 10000 / 10001）。
2. **席数**（`seatRange`）: 読むのは「N」「N席…」「N〜M席」「全N席」「総席数N席」「総N席」「計N席（席の種類の合計でないとき）」「カウンターN席のみ」だけ。
   「約」「程度」「前後」、内訳だけ（「カウンター6席＋テーブル3卓」）、「総席数140席（現在80席で営業）」のように食い違う書き方は不明。
   「20席以上」は、範囲（「19〜20席」）が閾値をまたぐときは不明にする。
3. **営業時間帯**: 「はい」は、読み取れた曜日のどこかが当てはまるとき。「いいえ」は **7曜日すべてが読み取れていて、どれも当てはまらないとき**だけ（読めない曜日が残るなら不明）。

## 4. 抜き取り（各条件につき3店を、その店のページの表示と見比べた）

方法: `/search` で条件を1つだけ押し、結果から seed 固定で3店を選び、店ページ `/restaurant/<ID>` の表示（営業時間・定休日・予算・席数・アクセス・予約ボタン・タグと本文）と、判定が合っているかを目視した。20 条件 × 3 店 = 60 店。

**見つけた食い違いと直した内容**: 1回目の抜き取りで、駐車場・テイクアウトの 6 店中 4 店（r413・r407 / r469・r410）が、店ページのどこにも該当の記載が無かった。
原因は、仕様の元に入れていた **highlights（特集記事の見出し）** は店ページに表示されない文だったこと（例: r413 は見出しに「共用駐車場100台」とあるだけ）。
そのため highlights を設備・特徴の元から外した（記載あり: 駐車場 58→38、テイクアウト 27→16、テラス 23→16、禁煙 35→25、子連れ 28→17、個室 74→72、カウンター 205→196）。
