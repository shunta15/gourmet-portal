# マチノワ特集記事 制作スペック（完全版）

**最終更新: 2026-05-24**

このドキュメントは「マチノワ特集記事を書く時のすべて」を集約する単一の正本である。

- **記事本文を書くとき**: このファイルだけ開けば足りる
- **自動化（cowork / CronCreate）を回すとき**: 併せて [`automation/runbook.md`](../../automation/runbook.md) を参照

---

## 0. 絶対遵守の前提

1. **マチノワ全記事は「マチノワ編集部」単一トーン**。teleapo 用・自動生成用などの派生トーンを作る概念は禁止
2. **author 固定**: `"マチノワ編集部"`
3. **品質目標**: 既存高品質 3 記事と区別がつかないこと
   - [`feature-qualia-meinohama`](../../lib/newGuideFeatures6.ts) 姪浜・夜デート系
   - [`feature-kinosha-nachikatsuura`](../../lib/newGuideFeatures6.ts) 郊外・観光地起点
   - [`feature-nishida-yao`](../../lib/newGuideFeatures6.ts) 住宅地・地元密着系
4. **noindex 公開**: FEATURES（公開一覧）には載せない、URL のみ有効
5. **店舗追加は明示指示があった時のみ**。勝手に増やさない

---

## 1. 目的

単なる店舗紹介ではなく、**「その街で、その店に行く理由」**が伝わる編集記事にする。
読者が記事を読んだあとに、**いつ・誰と・どう使う店なのか判断できる内容**にする。

## 2. メディア方針

マチノワは、**街で過ごす理由を増やす地域ポータル**です。
店舗だけを紹介するのではなく、**その店が街の中でどんな役割を持っているか、どんな時間に使いやすいか**まで伝えてください。

---

## 3. 記事構成

1. frontmatter
2. 導入文
3. 編集部が選ぶ5つのポイント
4. 編集部のひとこと
5. 最後に、歩き方

## 5. タイトル

地域名・店名・店の個性が伝わるタイトルにする。

### タイトル条件
- 地域名を入れる
- 店名を入れる
- 料理ジャンルや店の特徴を入れる
- 検索キーワードを自然に含める
- 煽りすぎない
- 「人気」「おすすめ」だけに頼らない

### タイトル例
> 姪浜の夜に灯る、創作イタリアンとカクテルの一軒。
> Kitchen&Bar Qualiaで過ごす、食事のあとまで心地いい時間

---

## 6. summary

- 80〜130字程度
- 検索結果で読まれる前提で、**地域名・店名・ジャンル・利用シーン**を自然に入れる

---

## 7. 導入文

- 300〜450字程度
- 最初に **街の空気** を描写する
- 次に、**その街の中で店舗がどんな存在なのか** を書く
- 最後に、**編集部目線で5つのポイントを紹介すると宣言** する

### 導入文に入れる要素
- エリア名、最寄り駅
- 街の雰囲気
- 店舗ジャンル
- 店の強み
- どんな日に行きたい店か
- 読者の利用シーン

---

## 8. 5つのポイント

| POINT | 役割 |
|---|---|
| POINT 01 | 店の核となる料理・商品・技術について書く |
| POINT 02 | 他店と違う特徴、通いたくなる理由を書く |
| POINT 03 | 素材・メニュー・ドリンク・コースなど具体的な魅力を書く |
| POINT 04 | 店内空間・席・雰囲気・誰と行きやすいかを書く |
| POINT 05 | アクセス・街歩きとの組み合わせ・使い方を書く |

### 各POINTの書き方
- POINT番号を入れる
- 小さな分類ラベルを入れる
- 見出しは具体的にする
- 本文は **400字前後** を目安にする
- 最後に **店舗情報メモを2つ** 入れる
- 抽象的な褒め言葉だけで終わらせない

### POINT形式

```
POINT 01
創作イタリアン・姪浜
### 食事の満足度を作る、創作イタリアンの軸

本文:
この店の料理の特徴、なぜ食事目的で選べるのか、どんな読者に向くかを書く。

メモ:
料理 パスタ・ピザ・リゾット・魚介料理・肉料理
用途 ディナー・記念日・普段使い
```

---

## 9. 編集部のひとこと

- 80〜150字程度
- 記事全体の余韻を作る短いコメントにする
- 説明を増やす場所ではなく、**編集部としての温度感** を伝える場所
- 「この街でこの店がどう見えるか」「どんな日に思い出したい店か」を短くまとめる

### 例
> 手打ち蕎麦 にし田は、八尾という街にしっかりと根付いている一軒。近鉄八尾の住宅街で、毎朝挽く粉と曜日替わりの蕎麦に向き合い続ける――その「日常を支える本気」が、暖簾の向こうから伝わってくる。八尾で蕎麦と聞いたら、まさに、編集部イチオシのお店です。

---

## 10. 最後に、歩き方

- 400〜500字程度
- 読者が **実際に行くときの使い方** を書く

### 必ず入れる内容
- 初訪問ならどう使うか
- デートならどう使うか
- 一人・少人数ならどう使うか
- 所要時間
- 予算感
- 混雑や予約の注意
- 営業時間や価格は変わる可能性があるため公式確認を促す

---

- 地域名 + バー
- 地域名 + 記念日
- 店名 + メニュー
- 店名 + 予約
- 店名 + アクセス

## 12. 文体

- マチノワ編集部として書く
- 少し情緒はあるが、ポエムにしすぎない
- 読者の判断材料を必ず入れる
- 自然な日本語で、読み物として気持ちよく読める文章にする
- 体温のある一文を入れる（「これ、地味に効く」「正直、外れない」など）
- AI 優等生文体（「〜することができます」「〜なのです」連発）禁止

---

## 13. 文字数

- **本文全体で 3000字以上** を必須とする
- 目安は 3000〜3500字
- ただし、**文字数を満たすための水増しは禁止**
- 読者の判断材料、具体的な利用シーン、料理・空間・アクセス・予算・注意点を増やして自然に厚みを出す

---

## 14. 禁止事項

### ユーザー受領分（記事品質）
- 店舗説明文をそのまま貼る
- 汎用的な褒め言葉で水増しする
- 店舗と関係ない観光情報を入れすぎる
- エリア外のスポットを混ぜる
- 公式確認できない情報を断定する
- 同じ締め文を使い回す
- AIが書いたような抽象表現を連発する
- 「最高」「絶対」「No.1」など根拠のない断定を使う
- 口コミを事実のように断定して引用する

### 過去事故由来の追加禁止表現
- 否定起点の褒め: 「素朴」「派手さはない」「奇をてらった〜ではない」「観光客向けの派手な店ではなく」
- 根拠なし最上級: 「日本一」「絶品」（出典あれば可）
- 客引き追従: 「呼び込みについていけば」等
- 年号付き料金: 「○○円（2026年現在）」→「公式情報をご確認ください」に置換
- 俗称・ネットスラング
- 「〜らしい」（推測）

## 15. 事実ソース／割愛ルール（2026-05-24 ユーザー明言）

- **事実ソース**: スプレッドシートに貼ってある GBP（Google Maps）URL を**必ず**参照する。これが唯一の一次情報源
- **推測は禁止**（過去のハルシネ事故のため）
- **GBP に出ていない情報は割愛**:
  - メニュー名・料理内容
  - 席数・席種
  - 客層・客単価
  - 雰囲気・内装の具体描写
  - ペアリング・酒の品揃え
  - 「〜だろう」「〜と思う」で書ける憶測情報すべて
- **割愛＝「公式情報をご確認ください」と書くのではなく、そもそも書かない**（その POINT を立地・周辺・アクセス論で組み立てる）

### GBP が取れなかった場合
- **記事を書かない。スキップして次の候補へ進む**
- 「住所不明だから抽象的に書く」は禁止（過去のハルシネ事故の原因）

## 16. 画像規約（2026-05-24 ユーザー明言・確定）

### 画像ソース許容範囲（その店舗の実物画像なら何でも可）
- Google Maps（GBP）の `grass-cs/` プレフィックス画像
- 公式ホームページの画像
- 公式 Instagram の投稿画像
- オーナー提供画像

**禁止**: 架空店舗の画像・他店の画像・Unsplash 等の汎用ストックフォト

### 必須画像
- `heroImage`: `/restaurants/teleapo-<slug>/hero.jpg`
- `ogImage`: hero と同一パスで OK
- POINT 01 の `images`: 実画像必須
- POINT 02 の `images`: 実画像必須

### 任意画像
- POINT 03〜05 の `images`: `[]`（空配列）。CSS が「画像イメージ」ラベル＋暗色背景を表示

### 画像が POINT 01・02 で1枚も揃わない場合
- **記事生成自体をスキップ**（画像なしの記事は作らない）

画像取得の curl 手順は [`automation/runbook.md`](../../automation/runbook.md) §画像取得 を参照。

## 17. ID／URL 命名規約（2026-05-24 ユーザー明言・確定）

- **id / key は店舗名のみ**（日本語OK）。`teleapo-feat-` 等のプレフィックス禁止
- URL: `machinowa.tokyo/feature/<店舗名>`
- 注釈（営業時間・移転・閉店等）は ID に入れない
  - 例: `OWL` ○ / `owl営業時間状況で変わります` ✗
- URL で問題になる記号は除外: `。` `/` `(` `)` `?` `&` `#` `%`
- 残してOK: 英数・ひらがな・カタカナ・漢字・`-`
- 旧 `/feature/teleapo-feat-*` は [`middleware.ts`](../../middleware.ts) で 301 リダイレクト救済済（既存6記事のみ）

## 18. ファイル出力

### 特集記事（feature）
- 追記先: [`lib/teleapo-features.ts`](../../lib/teleapo-features.ts)
- 末尾の `};` の直前に1ブロック追記
- key と id は §17 のルールに従う

### 店舗紹介（restaurant）
- 追記先: [`lib/teleapo-restaurants.ts`](../../lib/teleapo-restaurants.ts)
- URL: `machinowa.tokyo/restaurant/<店舗名>`

### TypeScript 型（FeatureArticle / lib/data.ts）

```ts
{
  id: "<店舗名>",                     // §17 ルール
  no: "",
  articleType: "guide" as const,
  kicker: "<英大文字キャッチ>",        // 例: "QUALIA MEINOHAMA"
  title: "<§5 タイトル>",
  titleHTML: "<2行構成・店舗名 <em></em>強調>",
  subtitle: "<業態 + エリア + シーン / 20〜35字>",
  lede: "<§7 導入文>",
  date: "<YYYY-MM-DD>",
  reading: "",
  author: "マチノワ編集部",
  heroImage: "/restaurants/teleapo-<slug>/hero.jpg",
  ogImage: "/restaurants/teleapo-<slug>/hero.jpg",
  ranking: [POINT 01〜05],
  sideArticles: [],
  quote: "<§9 編集部のひとこと / 80〜150字>",
  quoteCite: "マチノワ編集部",
  closing: "<§10 最後に、歩き方 / 400〜500字>",
}
```

各 POINT は:
```ts
{
  rank: "POINT 0X",
  rankNum: X,
  name: "<具体的な見出し>",
  cuisine: "<業態またはトピック>",
  area: "<市区町村>",
  purpose: "<その POINT の狙い・誰向けか>",
  desc: "<400字前後の本文>",
  images: [...],
  specs: [{ k: "<項目>", v: "<値>" }, { k: ..., v: ... }]  // 必ず2項目
}
```

## 19. 出力形式

- 記事本文は Markdown で起草
- 最終的に上記 TypeScript object に変換して `.ts` に追記
- 文中で引用・強調するときは **半角ダブルクォート `"` 禁止**（TypeScript 構文エラー）→ 日本語の `「」` を使う
