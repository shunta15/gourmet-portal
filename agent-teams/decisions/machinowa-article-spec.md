## 1. 目的

単なる店舗紹介ではなく、**「その街で、その店に行く理由」**が伝わる編集記事にする。
読者が記事を読んだあとに、**いつ・誰と・どう使う店なのか判断できる内容**にする。

## 2. メディア方針

マチノワは、**街で過ごす理由を増やす地域ポータル**です。
店舗だけを紹介するのではなく、**その店が街の中でどんな役割を持っているか、どんな時間に使いやすいか**まで伝えてください。

## 5. タイトル

地域名・店名・店の個性が伝わるタイトルにする。

### タイトル条件
- 地域名を入れる
- 店名を入れる
- 料理ジャンルや店の特徴を入れる
- 検索キーワードを自然に含める
- 煽りすぎない
- 「人気」「おすすめ」だけに頼らない

### タイトル例
> 姪浜の夜に灯る、創作イタリアンとカクテルの一軒。
> Kitchen&Bar Qualiaで過ごす、食事のあとまで心地いい時間

## 6. summary

- 80〜130字程度
- 検索結果で読まれる前提で、**地域名・店名・ジャンル・利用シーン**を自然に入れる

## 7. 導入文

- 300〜450字程度
- 最初に **街の空気** を描写する
- 次に、**その街の中で店舗がどんな存在なのか** を書く
- ~~最後に、編集部目線で5つのポイントを紹介すると宣言する~~（2026-10-13 廃止。記事の案内文は型C。§14 A のとおり lede は導入で自然に終える）

### 導入文に入れる要素
- エリア名、最寄り駅
- 街の雰囲気
- 店舗ジャンル
- 店の強み
- どんな日に行きたい店か
- 読者の利用シーン

---

## 8. 5つのポイント

| POINT | 役割 |
|---|---|
| POINT 01 | 店の核となる料理・商品・技術について書く |
| POINT 02 | 他店と違う特徴、通いたくなる理由を書く |
| POINT 03 | 素材・メニュー・ドリンク・コースなど具体的な魅力を書く |
| POINT 04 | 店内空間・席・雰囲気・誰と行きやすいかを書く |
| POINT 05 | アクセス・街歩きとの組み合わせ・使い方を書く |

### 各POINTの書き方
- POINT番号を入れる
- 小さな分類ラベルを入れる
- 見出しは具体的にする
- 本文は **400字前後** を目安にする
- 最後に **店舗情報メモを2つ** 入れる
- 抽象的な褒め言葉だけで終わらせない

### POINT形式

```
POINT 01
創作イタリアン・姪浜
### 食事の満足度を作る、創作イタリアンの軸

本文:
この店の料理の特徴、なぜ食事目的で選べるのか、どんな読者に向くかを書く。

メモ:
料理 パスタ・ピザ・リゾット・魚介料理・肉料理
用途 ディナー・記念日・普段使い
```

## 9. 編集部のひとこと

- 80〜150字程度
- 記事全体の余韻を作る短いコメントにする
- 説明を増やす場所ではなく、**編集部としての温度感** を伝える場所
- 「この街でこの店がどう見えるか」を、**その店の事実だけで**短くまとめる（「思い出したい店か」の定型は型C）

- 「〜と聞いたら思い出したい一軒だ」「覚えておきたい店だ」「編集部イチオシのお店です」のような**どの店にも言える締めは書かない**（§14-0 型C）。その店だけの事実（何を、いつ、どこで）で終える
- 事実が足りなくて80字に届かないときは、**短いまま**でよい（埋めるために型Cの定型を足さない）

### 例（旧例の末尾「八尾で蕎麦と聞いたら、まさに、編集部イチオシのお店です。」は型Cなので削除。店の事実で終わる）
> 手打ち蕎麦 にし田は、八尾という街にしっかりと根付いている一軒。近鉄八尾の住宅街で、毎朝挽く粉と曜日替わりの蕎麦に向き合い続ける――その「日常を支える本気」が、暖簾の向こうから伝わってくる。

## 10. 最後に、歩き方

- 400〜500字程度
- 読者が **実際に行くときの使い方** を書く

### 入れる内容（**事実が分かるものだけ**。分からない項目は書かない・触れない。§14-0 型A）
- 初訪問ならどう使うか
- デートならどう使うか
- 一人・少人数ならどう使うか
- 所要時間
- 予算感
- 混雑や予約の注意
- 営業時間や価格は変わる可能性があるため公式確認を促す（実用の注意として1回。固定形の連発は §14 B）
- 「分からないので書かない」と書くのは禁止。該当する文を作らずに飛ばす（400〜500字に届かなくてよい）

## 12. 文体

- マチノワ編集部として書く
- 少し情緒はあるが、ポエムにしすぎない
- 読者の判断材料を必ず入れる
- 自然な日本語で、読み物として気持ちよく読める文章にする
- 体温は**その店の事実の言い方**で出す（量・時間・手順・場所を具体的に）。「これ、地味に効く」「正直、外れない」のような**どの店にも貼れる相づちは禁止**（§14-0 型C）
- AI 優等生文体（「〜することができます」「〜なのです」連発）禁止

---

## 13. 文字数

- 目安は **3000〜3500字**。ただし**事実が足りないときは短くてよい**（2026-10-13 変更。旧: 3000字以上を必須）
- **文字数のために文を作ることは禁止**。事実が足りない分は、型A〜Eの文（分からなかったことの記述・決まり文句・行ったふり・裏付けの無い評価）で埋めず、その分だけ短くする
- 読者の判断材料、具体的な利用シーン、料理・空間・アクセス・予算・注意点のうち、**確かな事実がある分だけ**厚みを出す
- 注意: 検索に出す基準 `automation/emit-teleapo-indexable.mjs`（本文2500字以上・逃げ表現3個以下）は別に動く。短い記事は noindex のまま（URL は有効）になるが、それで正しい

## 14. 禁止事項

### 14-0. 🚨 文章の6つの型（2026-10-13 制定・サイトの表示と同じ基準・最優先）

サイトは、画面に出す直前に、次の6つの型の文を**文ごと取り除いている**（`lib/otherSiteRatings.ts` / `lib/thinSentences.ts`）。
取り除かれる文は書いても無駄で、残った文のつながりも崩れる。**最初から書かない。**
**事実が足りないときは、文を作って埋めずに、その分だけ短くする**（短いのは失敗ではない。水増しが失敗）。
生成後に `node scripts/check-article-sentences.mjs <記事ID>` が同じ型を機械的に調べる（当たれば公開前に直す）。

| 型 | 書かないもの | 実例（書いてはいけない文） | 代わりに |
|---|---|---|---|
| R | 他サイト（食べログ・Google の口コミ・Retty・ホットペッパー・SNS など）の評価・点数・星・口コミ/レビューの件数・口コミの中身の引用 | 「食べログ評価3.58で48席の個室も揃える。」「口コミでは大将とママの応対に触れる声が複数出ている。」「Googleマップの口コミには酢飯の炊き加減に触れる声もある。」 | 書かない。賞・選出（百名店・ミシュランの星）は事実なので書いてよい（出典つき） |
| A | 分からなかった・確認できなかったことを書く文 | 「座席数や内装の詳細を裏付ける一次情報は見当たらない。」「専用駐車場の有無は公開情報からは確認できない。」「詳細情報は非公開。」 | 分かったことだけ書く。分からないことは文にしない（触れずに飛ばす） |
| B | 調べ方・書き手の舞台裏 | 「ここでは確認できた事実だけを書く。」「先に正直なところを書いておく。」「店が公開している写真から読み取れるのは…」 | 書かない。事実をそのまま書く |
| C | どの店にも言える決まり文句・締めの定型・記事の案内文 | 「〇〇で麺と聞いたら、まず思い出したい店だ。」「覚えておきたい一軒だ。」「これ、地味に効く。」「まさに、編集部イチオシのお店です。」「…を5つの視点から紹介していく。」「…をここから見ていきたい。」「通う理由はここにある。」 | その店だけの事実（何を・いつ・どこで）で終える。事実で締められないなら、書かずに終える |
| D | 行ったふり（来店したかのような体験・感想） | 「棒寿しをひとくち食べると、そのことが少しわかる気がする。」「…というシェフのメッセージだと感じた。」「実際に足を運んでみないと伝わりにくい。」 | 事実の説明として書く（「〜を出している」「〜の席がある」）。感じた・分かった・食べてみたら、は書かない |
| E | 裏付けの無い評価・人気 | 「地元の食好きに支持されている。」「評判の店。」「人気のメニュー。」「地域に親しまれている。」「おすすめ。」「知る人ぞ知る一軒。」 | 根拠（出典つきの賞・選出、店が公式に出している数字や名称）があるときだけ。無ければ書かない |

- 残してよい: 営業時間・料金・予約・道順に結び付いた実用の注意（「営業時間や定休日は変わることがあるため、来店前に〜」。1記事に1回・言い換えは §14 B）、店が公式に出しているメニュー名・コース名（「おすすめ宴会コース」などの固有名称）
- 文を書き換えて型を避けるのは禁止（「支持されている」→「親しまれている」にしても同じ型E）。**根拠のある事実に置き換えるか、文ごと取る**
- 照合は語の検出（`scripts/check-article-sentences.mjs`）。語に当たらなくても、上の型に当てはまる文は書かない

### ユーザー受領分（記事品質）
- 店舗説明文をそのまま貼る
- 汎用的な褒め言葉で水増しする（→ 型C・E）
- 店舗と関係ない観光情報を入れすぎる
- エリア外のスポットを混ぜる
- 公式確認できない情報を断定する
- 同じ締め文を使い回す（→ 型C）
- AIが書いたような抽象表現を連発する
- 「最高」「絶対」「No.1」など根拠のない断定を使う
- 口コミを事実のように断定して引用する（→ 型R）
- 他サイトの点数・星・評価の高さ・口コミ/レビューの件数は文章に書かない（→ 型R。2026-10-11 オーナー指示。賞・選出の事実や出典の注記は別）

### 過去事故由来の追加禁止表現
- 否定起点の褒め: 「素朴」「派手さはない」「奇をてらった〜ではない」「観光客向けの派手な店ではなく」
- 根拠なし最上級: 「日本一」「絶品」（出典あれば可）
- 客引き追従: 「呼び込みについていけば」等
- 年号付き料金: 「○○円（2026年現在）」→「公式情報をご確認ください」に置換
- 俗称・ネットスラング
- 「〜らしい」（推測）
- 出どころを語る言い回し（2026-10-24 オーナー指示「公式ページからの引用ですみたいなのも全部やめて」）: 「公式サイトによると」「公式サイトには〜と書かれています」「〜と案内されています」「〜と載っています」「公式サイトの表示は」「Google マップの表示では」「〜とのこと」「引用」を文に入れない。事実は言い切りで書く（足さない・変えない）。残すのは、公式サイトへのリンクのボタンと、ページ下の「情報の出どころ」（出典の一覧）だけ

### 🚨 脱テンプレ規約（2026-05-29 制定・200本量産前の必須対策）

**背景**: teleapo 記事23本時点で定型句が「編集部が考える」31回・「訪問前に公式情報での確認を」43回・「5つのポイント」31回と頻出。closing は 33本中33本（100%）が「編集部が考える〜の使い方／黄金動線はこうだ」で始まり、Google の Helpful Content システムに「テンプレ量産サイト」と判定されサイト全体が順位下落するリスク。200本に増やす前に必ず守ること。

#### A. 全面禁止フレーズ（記事間で使い回すと検出される定型句）
| 禁止フレーズ | 代替方針 |
|---|---|
| 「編集部が考える〜（の使い方／黄金動線／動線）はこうだ」 | closing 冒頭は店の固有要素から書き出す（下記 C 参照） |
| 「初めてなら、まずは〜」「初訪問なら、まずは〜」 | 「最初の一杯は」「初回は」「迷ったら」等、店ごとに変える |
| lede 末尾の「今回は、〜5つのポイントに分けて紹介していく」 | lede は導入で自然に終える。ポイント数の宣言は不要 |
| 「〜の起点になってくれる一軒だ」「理由になる一軒」「〜と聞いたら思い出したい一軒だ」「覚えておきたい店だ」「編集部イチオシ」 | 締めは店ごとに固有の事実で（書けなければ書かずに終える。§14-0 型C） |

#### B. 「公式確認」表現の言い換え（同一フレーズの連発禁止・3パターン以上を回す）
- 「営業時間や定休日は変わることがあるため、来店前に最新情報を確かめておきたい」
- 「メニューや価格は時期で動くので、訪れる前に電話や公式SNSで確認を」
- 「内容は変更される場合があるため、事前に店へ問い合わせておくと確実だ」
- ※「訪問前に公式情報での確認を」の固定形は1記事に1回まで。複数POINTで繰り返さない

#### C. closing 書き出しのバリエーション指針（毎回違う型を選ぶ）
1. **店の固有要素起点**: 「化学調味料を使わない一杯を求めて清田区まで足を運ぶなら、半日の動かし方を決めておくと無駄がない。」
2. **時間軸起点**: 「この店を一日の中心に据えるなら、昼前から動き出すのが収まりがいい。」
3. **客層・シーン起点**: 「家族で訪れるか、一人で来るかで、この店の楽しみ方は変わる。」
4. **立地・道のり起点**: 「最寄り駅から店までの数分が、すでにこの一軒の入口になっている。」
5. **問い起点**: 「なぜわざわざこの街でこの店なのか——答えは、半日歩けば腑に落ちる。」
- 上記はあくまで例。同じ型を連続で使わず、店の個性に合う書き出しを毎回ゼロから組む

#### D. lede 書き出しのバリエーション
- 地名・立地の描写から入るのは可だが、「〇〇といえば〜」「〇〇駅から徒歩圏内」の構文連発を避ける
- 店の業態・成り立ち・名物から入る回も混ぜる（例: 「炭火家本舗 なんばやは、備長炭を〜」のように店名起点も可）

#### E. 自己チェック（記事完成後に必ず grep）
- closing が「編集部が考える」で始まっていないか
- 「初めてなら、まずは」「初訪問なら、まずは」を含まないか
- 「5つのポイントに分けて紹介」を含まないか
- ヒットしたら書き直してから公開する
- **機械の検査**: `node scripts/check-article-sentences.mjs <記事ID>`（§14-0 の型 R/A/B/C/D/E）。当たりが無くなるまで直す（`--fix` は落としてよい文だけ機械で取る）

## 15. 事実ソース／割愛ルール（2026-05-24 ユーザー明言）

- **🚨 絶対遵守（2026-05-26 ユーザー明言）**: スプシ **J列の Maps URL が示す店舗が絶対的に正しい**。店舗名（D列）と Maps URL が示す店舗が食い違って見えても、**Maps URL の店舗が事実**。
- **🚨 店舗特定の最初の一手は「Maps URL を直接開く」（例外なし・2026-05-27 強化）**:
  - 店舗名で WebSearch して同名別店舗を拾うのは**絶対禁止**
  - Chrome MCP navigate / WebFetch で Maps URL を開き、リダイレクト先の `/maps/place/<NAME>/@<lat>,<lng>/` から正式な店舗名・座標を確定してから、その住所＋店舗名で公式情報を集める
  - 自動化プロンプト（automation/local-pipeline.sh）の手順2はこの順序で固定
- 座標から逆引きしたり店舗名で再検索したりして「データ不整合」と勝手に判断するのは禁止（過去の判断ミス：点心厨房 桃花 = 京都の店なのに私が座標誤読で「川崎の店」と判断して permanent_error 化した事故あり）
- **事実ソース**: スプレッドシートに貼ってある GBP（Google Maps）URL を**必ず**参照する。これが唯一の一次情報源
- **推測は禁止**（過去のハルシネ事故のため）
- **GBP に出ていない情報は割愛**:
  - メニュー名・料理内容
  - 席数・席種
  - 客層・客単価
  - 雰囲気・内装の具体描写
  - ペアリング・酒の品揃え
  - 「〜だろう」「〜と思う」で書ける憶測情報すべて
- **割愛＝「公式情報をご確認ください」と書くのではなく、そもそも書かない**（その POINT を立地・周辺・アクセス論で組み立てる。「確認できなかった」と書くのも型A）。立地・周辺の事実も足りなければ、その POINT は短くてよい

### GBP が取れなかった場合
- **記事を書かない。スキップして次の候補へ進む**
- 「住所不明だから抽象的に書く」は禁止（過去のハルシネ事故の原因）

## 16. 画像規約（2026-05-24 ユーザー明言・確定）

### 画像ソース許容範囲（その店舗の実物画像なら何でも可）
- Google Maps（GBP）の `grass-cs/` プレフィックス画像
- 公式ホームページの画像
- 公式 Instagram の投稿画像
- オーナー提供画像

**禁止**: 架空店舗の画像・他店の画像・Unsplash 等の汎用ストックフォト

### 必須画像
- `heroImage`: `/restaurants/teleapo-<slug>/hero.jpg`
- `ogImage`: hero と同一パスで OK
- POINT 01 の `images`: 実画像必須
- POINT 02 の `images`: 実画像必須

### 任意画像
- POINT 03〜05 の `images`: `[]`（空配列）。CSS が「画像イメージ」ラベル＋暗色背景を表示

### 画像が POINT 01・02 で1枚も揃わない場合
- **記事生成自体をスキップ**（画像なしの記事は作らない）

画像取得の curl 手順は [`automation/runbook.md`](../../automation/runbook.md) §画像取得 を参照。

## 17. ID／URL 命名規約（2026-05-24 ユーザー明言・確定）

- **id / key は店舗名のみ**（日本語OK）。`teleapo-feat-` 等のプレフィックス禁止
- URL: `machinowa.tokyo/feature/<店舗名>`
- 注釈（営業時間・移転・閉店等）は ID に入れない
  - 例: `OWL` ○ / `owl営業時間状況で変わります` ✗
- URL で問題になる記号は除外: `。` `/` `(` `)` `?` `&` `#` `%`
- 残してOK: 英数・ひらがな・カタカナ・漢字・`-`
- 旧 `/feature/teleapo-feat-*` は [`middleware.ts`](../../middleware.ts) で 301 リダイレクト救済済（既存6記事のみ）
