# 利用シーン特集の書き方（ライター向け・1ページ）

正本は `agent-teams/decisions/machinowa-article-spec.md`（以下 spec）。ここはシーン特集に当てはまる要点だけ。
出力の形式は [SCHEMA.md](./SCHEMA.md)、材料は `candidates.json`。書いたら `node automation/scene-articles/emit.mjs --check` で機械検査する。

## 絶対に守ること

1. **署名は「マチノワ編集部」の単一トーン**（spec §0・§12）。派生トーンを作らない。AI 優等生文体（「〜することができます」「〜なのです」の連発）は禁止。少し情緒はあってもポエムにしない。
2. **事実だけ書く。** 使ってよい事実は `candidates.json` の `stores[店ID]`（住所・最寄り駅・営業時間・定休日・席・予算・業態・タグの根拠）だけ。データに無いこと（メニュー名・味・席数・客層・雰囲気・内装・酒の品揃え・混雑）は**書かない**。「公式情報をご確認ください」で埋めるのでなく、そもそも書かない（spec §15）。推測の語尾（〜だろう・〜らしい・〜と思う）も禁止。
3. **来店体験を創作しない。** 「実際に訪れた」「食べてみた」「伺った」「いただいた」「取材した」前提の文は書けない。店に行っていない編集部が書く記事である。
4. **星評価・口コミ・レビュー・評判・評価に触れない。** 数字の評価も、口コミの引用や言い換えも禁止。
5. **誇張しない。** 「最高」「絶品」「必ず」「屈指」「随一」「有数」「最も」「日本一」「絶対」「No.1」「唯一無二」「究極」は使えない（emit が止める）。「人気」「おすすめ」は根拠が本文に無ければ使わない。否定起点の褒め（素朴・派手さはない）も禁止。
6. **店は候補の `storeIds` から選ぶ。** 候補にない店・新しい店・架空の店は載せない（店の追加は明示指示があるときだけ）。実写画像のない店は emit が記事から外す。

## シーン特集で特に大事なこと

- **タグの根拠を本文で示す。** その店がなぜこのシーン（ランチ・個室・宴会・深夜営業…）に当たるのかを、データの事実で書く。例: 営業時間 `11:30–14:30` なら昼営業の時間帯を書く、席の表記に「個室」があるなら席の表記をそのまま引く。使った事実は `factsUsed` にも挙げる。
- **`storeBasis` が `tag-only` の店は根拠が tags の付与だけ**。シーン適性を断定しない。店データにある別の事実（立地・業態・営業時間）で書くか、記事から外す。
- **日付・価格・営業時間は変わりうる。** 予算や営業時間に触れたら、確認を促す一文を入れる。言い回しは記事内・記事間で3パターン以上回し、「訪問前に公式情報での確認を」の固定形は1記事に1回まで（spec §14 B）。年号付きの料金（「○○円（2026年現在）」）は書かない。
- **地域名は店データに合わせる。** `nagoya` は愛知県全域（名古屋市の外の店も入る）、`hyogo` は兵庫県全域など、地域名と都道府県が一致しないことがある。候補の `prefs` と、`stores[店ID].town`（街）を見て、街の名前を正確に書く。
- **順位ではない。** 項目の並びは順位でなく、並べ方の意図（営業時間順・街順など）が本文から分かるようにする。「1位」「No.1」は書かない。

## 各店の書き分け（脱テンプレ規約 spec §14）

- 店ごとに**書き出しの型を変える**（営業時間起点・立地起点・業態起点・席の表記起点・最寄り駅起点…）。同じ構文の連発、同じ締めの使い回しは禁止。
- 次の定型は使わない: 「編集部が考える〜はこうだ」「初めてなら、まずは」「初訪問なら、まずは」「5つのポイントに分けて紹介」「〜の起点になってくれる一軒」「〜理由になる一軒」。
- `closing` は**この記事固有の要素から書き出す**（シーン・街・営業時間帯・店の並び方）。型の例は spec §14 C。lede も同様（spec §14 D）。
- `heading`（小見出し）は具体的に。抽象的な褒め言葉だけで終わらせず、データにある事実（最寄り駅・営業時間・業態・席の表記）で書く。

## 文量の目安

lede 150〜500字 / 各店 body 120〜600字 / closing 150〜600字（外れても警告のみ）。水増しはしない。読者の判断材料（いつ・誰と・どう使えるか）を、データの事実で厚くする。

## 書く前後のチェック

- [ ] 本文の事実がすべて `candidates.json` の店データにある（`factsUsed` と一致する）
- [ ] 来店したような表現・口コミ・評価・誇張がない
- [ ] 各店の書き出しと `closing` の型が記事内で重なっていない
- [ ] `node automation/scene-articles/emit.mjs --check` が通る
