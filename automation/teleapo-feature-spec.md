# テレアポ経由 店舗特集記事（1店舗＝1記事）生成仕様

マチノワ（machinowa.tokyo）の「1店舗を主役にした特集記事」を作る。出力は **JSON 1個**。

## 出力JSON（このキーだけ・過不足なし）

```json
{
  "articleId": "店舗名から記号と空白を除いた文字列（日本語可）",
  "kicker": "ローマ字の小見出し 例 SUMIYAKI MITSUI OKAYAMA",
  "title": "30〜48字。店名＋エリア＋料理の性格を含む記事タイトル",
  "titleHTML": "短い装飾タイトル。必ず <br> と <em></em> を含む 例 三ツ井、<br>柳町の<em>炭火。</em>",
  "subtitle": "20〜40字。料理ジャンル＋エリアを端的に",
  "lede": "導入文 250〜360字。街の情景 → 店の位置づけ → どんな人に向くか",
  "ranking": [ POINT を5つ（下記） ],
  "quote": "記事の要約 150〜200字。最後は必ず「です。」で締める",
  "quoteCite": "マチノワ編集部",
  "closing": "締めの実用ガイド 350〜520字。誰とどう使うか・所要時間・予算目安・予約や営業の勘所"
}
```

### ranking の各要素（必ず5つ、POINT 01〜POINT 05）

```json
{
  "rank": "POINT 01",
  "rankNum": 1,
  "name": "そのPOINTの見出し（20〜35字）",
  "cuisine": "POINTの性格ラベル",
  "area": "市区町村レベルの所在地（全POINTで同じ値）",
  "purpose": "そのPOINTが読者に何を示すかを一文で",
  "desc": "本文 320〜480字。情景と実用を両立させる",
  "specs": [ { "k": "ラベル", "v": "値" }, { "k": "ラベル", "v": "値" } ]
}
```

### POINT 5本の推奨の軸
1. **料理の核**（看板料理・食材・調理法）— `cuisine` 例:「炭焼き×会席」
2. **通いたくなる理由**（この店ならではの魅力・もう一度使いたくなる点）
3. **コース・予算・営業**（使い分け、価格の目安、営業日/定休）
4. **空間・席・誰と行くか**（カウンター/個室/席数、向く利用シーン）
5. **アクセス・街での使い方**（最寄り駅と徒歩分数、街と組み合わせた過ごし方）

## トーン（厳守）
- 「**マチノワ編集部**」トーン。落ち着いた編集者目線。煽らない。派生トーン禁止。
- 情景描写と実用情報を両立。読者が「行くかどうか」を判断できる材料を書く。
- 5本のPOINTが同じ言い回しの繰り返しにならないこと（脱テンプレ）。

## 🚫 禁止事項（1つでも違反したら不合格）
- **評価点・★・レビュー件数・口コミ件数を一切書かない**（例:「Google評価4.3」「口コミ200件」は絶対NG）
- **誇張禁止**:「日本一」「西日本最大級」「絶品」「必食」など出典なき最上級表現
- **根拠のない「人気」「おすすめ」**
- **営業時間・価格を断定しない**。必ず「訪問前に公式・電話で確認」の趣旨を本文かspecsに添える
- **年号付き料金**（「〇〇円（2024年現在）」）→「訪問前に確認」に置き換える
- **事実の創作禁止**: 受賞歴・ミシュラン・行列・有名人来店・席数の具体数字などを、裏が取れていないのに書かない
- **店名から場所を推測しない**（過去に大事故あり）。所在地は与えられた住所とMaps URLが絶対の正
- 俗称・ネットスラング

## 事実の取り方
- 与えられた **住所** と **Google Maps URL** が絶対の正。
- 公式サイト・公式SNSがあれば料理/コンセプト/営業時間/席の情報を取る。
- 食べログ等の**文章コピペは禁止**（ToS違反）。事実だけを拾って自分の言葉で書く。
- **評価・口コミ件数は取得も記載もしない。**
- 情報が薄い店は、無理に埋めず「確かな事実＋街の文脈」で厚みを出す。嘘で埋めるより遥かに良い。

## 文量チェック（提出前に自分で数える）
- lede 250〜360字 / 各 desc 320〜480字 / quote 150〜200字 / closing 350〜520字
